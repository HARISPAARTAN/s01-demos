# S01 Projektmanagement – 24 Shareable Website Demos: Design Spec

Date: 2026-10-08
Status: approved in brainstorming, awaiting user review of this document

## 1. Goal

Recreate the company website https://www.s01-pm.de/ (WordPress + Elementor) as
24 distinct, fully navigable, shareable demo websites. Every demo uses the same
S01 content, is available in German and English, and opens with a full-screen
looping video hero in the style of https://www.spacex.com/. The demos are for
internal review only ("demo only"); the supervisor picks a design direction.

Deliverable: public links on GitHub Pages, one index gallery plus 24 demos.

## 2. Decisions made during brainstorming

| Topic | Decision |
|---|---|
| Meaning of "20+ demos" | 24 full-site designs, same content, different look and layout |
| Sharing | Public web links on GitHub Pages, repo under the user's GitHub account |
| Language | German default plus EN/DE toggle on every page |
| Hero video | S01 web trailer from the live site plus three free Pexels clips, rotated across demos |
| Build approach | Static generator (Node) with a shared component kit; plain HTML/CSS/JS output |
| Pages per demo | All 8: Startseite, Services, Projekte, Unternehmen, Karriere, Kontakt, Impressum, Datenschutz |

## 4. Architecture

### 4.1 Repository layout (local: `E:\Work\Task 4`, GitHub: `s01-demos`, public)

```
content/
  site.de.json          all German text, structured by page and section
  site.en.json          English, identical key structure
  slugs.json            page file names per language
assets/
  video/                trailer.mp4, powerlines.mp4, windfarm.mp4, substation.mp4 + poster jpg each
  img/                  logo-lang.svg, logo-kurz.svg, Pexels photos for sections
  thumbs/               gallery thumbnails (generated by shots.js, committed)
kit/
  components/           one module per section, each exporting named variants
  base.css              reset, token scaffold, shared mechanics (hero, accordion, menu, badge)
  base.js               runtime: mobile menu, accordion, video fallback, demo form, demo badge
demos/
  01-original/ … 24-timeline-story/
    demo.json           recipe: name, fonts, variants, video, scheme
    theme.css           tokens and demo-specific overrides
build/
  build.js              renders dist/
  check.js              validates dist/ and content parity, exits non-zero on failure
  shots.js              Playwright screenshots + smoke checks, writes assets/thumbs/
  serve.js              tiny static server for local preview and shots.js
.github/workflows/deploy.yml
docs/superpowers/specs/ this spec and later the plan
dist/                   generated, git-ignored
```

### 4.2 Content model (`content/site.<lang>.json`)

Top level: `meta` (siteName, tagline, company {name, street, city, email, phone,
phoneMobile, iso}, nav [{page, label}], footerNav [{page, label}], ui strings
such as "Mehr erfahren", "Kontakt aufnehmen", "Menü", "Alle Demos", form labels,
demo notice) and `pages` with one object per page: `home`, `services`,
`projects`, `company`, `careers`, `contact`, `imprint`, `privacy`.

Each page object contains its sections as named keys with plain strings and
arrays, e.g. `pages.home.services.items[] = {id, title, text}` and
`pages.services.items[] = {id, title, text, bullets[]}`. Service ids are
language-neutral and used as anchors: `project-controls`, `scheduling`,
`interfaces`, `risk`, `documentation`, `consulting`.

`slugs.json` maps page keys to file names per language:

| page | de | en |
|---|---|---|
| home | index.html | index.html |
| services | services.html | services.html |
| projects | projekte.html | projects.html |
| company | unternehmen.html | company.html |
| careers | karriere.html | careers.html |
| contact | kontakt.html | contact.html |
| imprint | impressum.html | imprint.html |
| privacy | datenschutz.html | privacy.html |

The English text is a translation written during implementation, flagged for
supervisor review. The build fails if the DE and EN key trees differ.

### 4.3 Component kit (`kit/components/*.js`)

Each component module exports an object of variant functions
`(ctx) => htmlString`, where `ctx` carries `lang`, `t` (content), `demo`
(recipe), `page` key, `paths` (relative links to pages, assets, other
language) and helpers (`esc`, `link`). Variants:

| Component | Variants |
|---|---|
| nav | `transparent` (over hero, solid after scroll), `solid`, `sidebar`, `hamburger` (logo + burger, full-screen overlay), `pill` (floating centered) |
| hero | `bottom-left` (SpaceX), `centered` (two CTAs, scroll cue), `glass` (frosted card), `split` (video left, text right), `snap-stack` (home sections become 100vh scroll-snap panels) |
| services | `grid`, `numbered`, `bento`, `scroll` (horizontal snap), `accordion`, `rows` (alternating image rows), `timeline` |
| feature | `columns`, `tabs`, `stats` |
| projects | `cards`, `timeline`, `table`, `masonry` |
| faq | `accordion`, `two-column` |
| cta | one layout, themed |
| footer | `columns`, `minimal`, `mega` |
| contact | `split` (form + info), `centered` |
| careers, company, legal | one layout each, themed |
| badge | demo badge "NN/24 · Alle Demos", dismissable |

Page composition is fixed for all demos (home: hero, intro, services, closing,
feature, faq, cta; other pages mirror the live site order). Variety comes from
variant choice, tokens and theme CSS.

### 4.4 Demo recipe (`demos/<id>/demo.json`)

```json
{
  "id": "02-cinematic",
  "order": 2,
  "name": "Cinematic",
  "description": { "de": "…", "en": "…" },
  "scheme": "dark",
  "fonts": { "google": "Inter:wght@400;600;800", "heading": "'Inter', sans-serif", "body": "'Inter', sans-serif" },
  "variants": { "nav": "transparent", "hero": "bottom-left", "services": "numbered", "feature": "columns", "projects": "cards", "faq": "accordion", "footer": "columns", "contact": "split" },
  "video": "powerlines"
}
```

`theme.css` defines the tokens consumed by base.css and components:
`--bg, --fg, --muted, --surface, --accent, --accent-fg, --border, --radius,
--shadow, --font-heading, --font-body, --hero-overlay, --max-width, --section-y`
plus any demo-specific rules (grid lines, blobs, diagonal cuts, parallax).

### 4.5 Build pipeline (`node build/build.js`)

1. Load both content files and slugs; verify key parity.
2. Load every `demos/*/demo.json`; verify each variant name exists and the
   video key exists in assets.
3. For each demo × language × page: render the `<html lang>` document with head
   (title, description, Google Fonts link, base.css, theme.css, hreflang
   alternates), body (nav, page sections, footer, badge, base.js).
4. Copy `assets/` to `dist/assets/` and each `theme.css` to `dist/<id>/theme.css`;
   `base.css` and `base.js` to `dist/kit/`.
5. Render `dist/index.html`: gallery with a card per demo (thumbnail from
   `assets/thumbs/<id>.jpg`, accent-colored placeholder if missing, name,
   description, DE and EN buttons) and a credits footer.

All links are relative, so the output works under `/s01-demos/` on GitHub
Pages and from a local server without a base-path setting.

### 4.6 Output URLs

- Gallery: `https://harispaartan.github.io/s01-demos/`
- Demo page: `https://harispaartan.github.io/s01-demos/02-cinematic/de/services.html`
- Same page in English: `…/02-cinematic/en/services.html`
- Shared assets: `…/s01-demos/assets/…` (videos stored once)

## 6. Video hero behavior

- Markup: `<video autoplay muted loop playsinline preload="metadata" poster>`
  with one mp4 source, `aria-hidden="true"`; CSS `position:absolute; inset:0;
  object-fit:cover`; section `min-height:100svh`.
- Poster shows until playback starts; if autoplay is blocked or the file fails
  (`error` event), the poster remains and layout does not shift.
- `prefers-reduced-motion: reduce` or `navigator.connection.saveData`: video is
  not autoplayed; poster plus a small play button is shown.
- Each theme sets `--hero-overlay` (gradient) for headline contrast.
- Stock clips downloaded at 1280×720 (or the nearest Pexels size), target under
  8 MB each; trailer used as-is (2.6 MB). A poster jpg is produced per clip by
  screenshotting the first frame with Playwright, since ffmpeg is not installed.

Candidate Pexels clips (final choice at implementation after checking size):
- powerlines: https://www.pexels.com/video/power-lines-on-transmission-towers-9813696/ or https://www.pexels.com/video/aerial-view-of-open-fields-with-power-lines-33055876/
- windfarm: https://www.pexels.com/video/drone-footage-of-wind-turbines-7048403/ or https://www.pexels.com/video/aerial-sunrise-view-of-wind-turbines-in-a-field-35440278/
- substation: https://www.pexels.com/video/a-large-electrical-substation-with-several-power-lines-27844418/ or https://www.pexels.com/video/close-up-shot-of-insulators-in-substation-10058463/

Section photos: free Pexels photos (substation, pylons, engineers with hard
hats, control room, wind farm, documents), downloaded at about 1600px wide,
listed with author in `CREDITS.md` and in the gallery footer.

## 7. Language toggle

- Two pre-rendered trees per demo (`/de/`, `/en/`). The toggle in the nav is a
  plain link to the same page in the other language. `<link rel="alternate"
  hreflang>` is emitted for both.
- The gallery offers DE and EN entry buttons per demo.

## 8. Navigation and links

- All nav items, footer links, logo, "Mehr erfahren" (to `services.html#<id>`),
  CTA buttons (to the contact page), career apply buttons (to
  `mailto:recruiting@s01-pm.de`) are working relative links. The active page is
  marked with `aria-current="page"`.
- Mobile: hamburger button toggles the menu with `aria-expanded`; Escape closes.
- Demo badge: fixed bottom-right pill "NN/24 · Alle Demos" linking to the
  gallery, plus a close button; dismissal stored in `sessionStorage`.

## 9. Forms and legal pages

- Contact form: HTML5 required fields and email type; on submit, JS prevents
  the request and shows a localized "Demo – Nachricht wurde nicht gesendet"
  confirmation. No backend.
- Impressum: real company details as listed in section 3.
- Datenschutz: structured placeholder (section headings: Verantwortlicher,
  Hosting, Kontaktformular, Ihre Rechte) with the company details and a visible
  note "Demo – der rechtsverbindliche Text wird von S01 bereitgestellt".
- No cookie banner (nothing is tracked), no analytics.

## 10. Accessibility and responsiveness

- Skip link, landmarks (`header`, `nav`, `main`, `footer`), one `h1` per page,
  logical heading order.
- Accordions and menus use `button` with `aria-expanded` / `aria-controls`.
- `:focus-visible` style per theme; body text contrast of at least 4.5:1
  verified from tokens at build time (`--fg` on `--bg`, `--accent-fg` on `--accent`).
- Mobile-first CSS, breakpoints 640px and 1024px; 16px side gutter; no
  horizontal page scroll. Every demo checked at 390px and 1440px widths.

## 11. Deployment

- Public repo `s01-demos` on the user's GitHub account, created with `gh repo create`.
- `.github/workflows/deploy.yml`: on push to `main`, checkout, Node 22,
  `node build/build.js && node build/check.js`, upload `dist/` as the Pages
  artifact, deploy with `actions/deploy-pages`.
- Pages enabled via `gh api -X POST repos/<owner>/s01-demos/pages -f build_type=workflow`.
- Thumbnails are generated locally and committed, so CI needs no browser.

## 12. Verification

- `node build/check.js` (also run in CI): internal `href` and `src` resolve to
  files in `dist/`; DE/EN key parity; per page: one `h1`, non-empty `title`,
  correct `lang`, six nav links, toggle target exists; no `undefined`,
  `[object Object]` or `NaN` in HTML; contrast rule from section 10.
- `node build/shots.js`: starts `serve.js`, opens every demo home in DE at
  1440×900 and 390×844 and one subpage per demo, asserts no console errors,
  `video` present, at least 6 nav links; saves `assets/thumbs/<id>.jpg`.
- Live: after the workflow succeeds, `curl -I` on the gallery and three deep
  links per demo returns 200; manual pass in Chrome on five demos (video
  autoplays, toggle works, mobile menu opens).

## 13. Build-time error handling

- Missing content key: error naming language, page and key path.
- Unknown variant or video key in a `demo.json`: error listing valid names.
- Missing asset referenced by a component: error naming demo and path.
- Any check failure exits with a non-zero code and fails the CI deploy.

## 14. Delivery phases

1. Content files (DE + EN), kit, build, check, serve, deploy workflow, demos
   01 and 02, first live links.
2. Demos 03 to 12.
3. Demos 13 to 24, shots and thumbnails, CREDITS.md, final live checks.

## 15. Out of scope

- No CMS or WordPress theme export, no backend, no analytics, no cookie consent,
  no SEO work beyond titles and descriptions, no real Datenschutz legal text.
- The custom "Frktn" font is replaced by Manrope in demo 01.
- Live-site iStock photos are not copied; free Pexels photos are used and can be
  swapped by the company later.
